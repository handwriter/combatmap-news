# Combat Map — новости и официальный пул карт

Новости для панели в главном меню игры. Редактируются через сайт, публикуются автоматически,
**без пересборки и релиза игры**.

| Что | Адрес |
|---|---|
| Редактор (Sveltia CMS) | https://handwriter.github.io/combatmap-news/admin/ |
| Предпросмотр карточек | https://handwriter.github.io/combatmap-news/ |
| Фид для игроков | https://handwriter.github.io/combatmap-news/v1/news.json |
| Каталог карт | https://handwriter.github.io/combatmap-news/v1/maps.json |

## Как опубликовать новость

1. Открыть редактор → **Sign In with Token** → вставить свой GitHub-токен (см. ниже).
2. **News → New News item**. Обязательны только **Title (en)** и **Published at**; картинка,
   текст и ссылка — по желанию (пустые блоки в карточке не показываются; вся карточка — ссылка). Переводы ru / tr / fr / ar
   — на вкладках языков; чего нет, игроки увидят на английском.
3. Сохранить → через 1–2 минуты новость в `news.json`, игроки увидят её при следующем входе
   в главное меню (CDN GitHub Pages кэширует до 10 минут). Черновиков нет: сохранённое сразу
   публикуется, заранее подготовленную новость прячьте полем **Show from**.

Показ по расписанию — поля **Show from / Show until** (UTC): новость можно выложить заранее,
игра сама покажет и скроет её. Ограничение по версии игры — **Min / Max game version** (`0.107`).
Порядок: **Priority** по убыванию, при равенстве — новее выше; в меню максимум 10 новостей.

Каждое сохранение — коммит в `main`. Workflow **Publish game content** проверяет все записи; если что-то
не так (нет английского заголовка, ссылка не https, неверные даты),
сборка падает, GitHub присылает письмо, а игроки продолжают видеть прошлую версию фида.

## Как управлять картами

1. В том же редакторе открыть **Maps → New Map**.
2. Задать **Name**, загрузить **Map JSON**, полученный из встроенного редактора игры.
   Личные карты сохраняются в папке `maps/personal` внутри папки данных игрока
   (`Application.persistentDataPath`); на Windows это `%USERPROFILE%/AppData/LocalLow/<CompanyName>/<ProductName>/maps/personal`.
3. **Enabled** включает карту в официальный пул. Выключение временно убирает её;
   удаление записи убирает её из пула до повторного добавления.
4. **Order** задаёт порядок: меньшее значение выше, при равенстве — сортировка по ID.
5. Чтобы обновить карту, заменить файл в **существующей записи**. Название можно менять,
   имя файла самой записи сохранять: это постоянный ID карты. Имя загруженного JSON и `id` внутри него
   могут отличаться от ID каталога — игра различает эти значения.

Начальный каталог содержит 14 карт из игры. Активные карты проверяются и публикуются вместе
с новостями: число сторон должно совпадать с `maxPlayers` (2–8), количество клеток — с размерами
сетки, JSON должен соответствовать `schema/map.schema.json`. Размер файла — до 16 МиБ.
Загрузка файлов по внешним адресам не поддерживается. Ошибка активной карты отменяет весь
деплой, предыдущая публикация остаётся доступной. Отключённая карта не публикуется и её содержимое не проверяется.

Клиент с поддержкой каталога проверяет его при открытии главного меню, не чаще раза в 10 минут.
Новые карты скачиваются в фоне; выбрать их можно после завершения загрузки. Для обновлённой карты
до успешного скачивания доступна прежняя версия. Без сети используется сохранённый каталог,
при первом запуске — встроенный набор. Успешно полученный пустой каталог убирает все официальные
карты, встроенный набор их не возвращает. Личные карты остаются доступны.

В игре официальный ID имеет вид `official:riverlands`. Встроенный редактор создаёт личную копию
официальной карты; обновления сайта её не меняют. Уже открытое лобби сохраняет исходную версию
карты, даже если на сайте её заменили или удалили. Старые клиенты продолжают работать со своим
встроенным набором; для подключения каталога требуется один релиз игры.

Удаление записи не удаляет загруженный исходный JSON. Ненужный файл можно удалить отдельно
из библиотеки файлов, когда на него больше не ссылаются активные записи. В опубликованный сайт
попадают только файлы активных карт, под именами с хэшем содержимого.

## Доступ для редактора

1. Владелец репо: **Settings → Collaborators → Add people** (роль Write).
2. Редактор: GitHub → **Settings → Developer settings → Fine-grained tokens → Generate new token**:
   - Repository access: *Only select repositories* → `handwriter/combatmap-news`;
   - Permissions → Repository → **Contents: Read and write**;
   - срок действия — по вкусу (после истечения выпустить новый).
3. Токен вводится в редакторе один раз и хранится только в браузере.

## Устройство

```
admin/            редактор: index.html (Sveltia CMS) + config.yml (поля формы)
content/news/     одна новость = один JSON (Sveltia i18n single_file: { en: {...}, ru: {...} })
content/media/    загруженные картинки-оригиналы
content/maps/     записи официального каталога: title, file, enabled, order
content/map-files/ загруженные игровые JSON
site/index.html   страница предпросмотра
schema/           news-feed.schema.json — контракт фида с игрой (NewsFeedDto.cs)
                  maps-feed.schema.json — контракт каталога; map.schema.json — формат карты
scripts/build.mjs валидация + сборка dist/ (картинки → JPEG 640×360, имя = sha1)
scripts/maps.mjs  проверка карт + FNV-1a 64, без изменения исходного JSON
```

Локально (Node 20+):

```bash
npm ci
npm test
npm run build   # dist/v1/news.json, dist/v1/maps.json, dist/v1/maps/*.json, dist/v1/img/*.jpg
```

Совместимость: фид лежит под `/v1/`. Добавлять новые необязательные поля можно;
ломающие изменения — только в новый `/v2/`, чтобы старые версии игры продолжали работать.
